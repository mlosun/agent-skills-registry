# 贡献指南

> 如何给 agent-skills-registry 添加 skill、更新安全规则、参与维护。本文面向想贡献的人。

## 一、核心流程：添加一个 skill 源

本仓库是**精选源**——不是自动镜像所有 GitHub skills，而是人工挑选值得入库的来源。整体流程：

```
1. 选择来源仓库（需含 SKILL.md，可为合集或单 skill）
2. 运行 import.py 入库（自动：枚举 → 复制 → 安全扫描 → 写元数据）
3. 查看安全扫描结果，人工复核 risk 标签
4. 低谷时段跑 translate.py（补中文）→ enrich.py（生成推荐+标签）
5. 检查 index.yaml 与 git diff，提交
```

### 1.1 入库

```bash
# 单个来源仓库（URL 或 owner/repo）
python3 -m scripts.import https://github.com/owner/repo

# 合集仓库自动枚举所有 SKILL.md；单 skill 仓库同逻辑
# 默认跳过 in-progress/deprecated 等半成品分类
python3 -m scripts.import owner/repo --include-drafts   # 连半成品一起
python3 -m scripts.import owner/repo --force            # 已存在则覆盖重入
python3 -m scripts.import owner/repo --dry-run          # 演练不写盘
```

入库后生成：

- `skills/<owner>/<repo>/[<category>/]<skill>/`（镜像 + 上游辅助文件 + 分类 README）
- 每 skill 的 `skill-meta.yaml`（risk 标签 + upstream_sha）
- 每 skill 的 `security-report.md`（扫描报告）

### 1.2 人工复核（重要）

**入库只是第一道关，人工审核是关键**。核对：

- 扫描结论是否合理（误报 vs 真实风险，见下方「安全规则」）
- skill 是否有实际价值（精选标准：能用、维护活跃、有明确使用场景）
- 是否与已有 skill 重复（同名不同来源会并存，评估是否值得保留两个）

### 1.3 内容化（中文描述 + 推荐 + 标签）

DeepSeek 有**峰谷定价**（工作日北京时间 09-12/14-18 全价，其余含周末 5 折）。translate/enrich 内置时段护栏，**高峰时段默认拒绝运行**：

```bash
# 低谷时段运行（自动放行）
python3 -m scripts.translate    # 补缺的中文描述
python3 -m scripts.enrich       # 生成推荐理由 + 场景标签

# 高峰时段想跑需 --force（接受全价，不推荐）
python3 -m scripts.translate --force
```

## 二、安全规则

### 2.1 规则库结构

规则库 `rules.yaml` **独立于引擎** `security_scan.py`——增删规则只改 `rules.yaml`，不改代码。

规则字段：`id` / `name` / `severity` / `file_types` / `matchers` / `suggestion`

- `severity`：`block`（命中→high）/ `warn`（命中→medium）
- `file_types`：`all` / `script` / `doc` / `config` / `executable`
- `matchers` 类型：
  - `literal`：子串匹配
  - `regex`：正则匹配（`pattern`）
  - `pair`：组合检测（`a` 与 `b`，可设 `scope: same_line` 或 `same_file`）

### 2.2 如何加一条规则

在 `rules.yaml` 对应规则的 `matchers` 列表追加即可。例（给 R1 加 git 危险命令检测）：

```yaml
      - type: regex
        pattern: 'git\s+reset\s+--hard\b'
```

### 2.3 规则设计经验（避免误报）

1. **警惕"提及即命中"**：文档/代码里出现 `sudo`/`rm -rf` 不一定是危险操作。优先用组合检测（`pair` + `scope: same_line`），把无上下文的关键词降为 warn 或移除。
2. **变量赋值 vs 真实凭据**：R2 的 `token=` 若匹配 `TOKEN = generateToken()`（合法代码）是误报。仅当值带引号或为高熵串（16+ 位混合）才命中。
3. **改完必须重扫**：规则更新后用 `--rescan-all` 批量刷新全部 skill 的 risk 与报告：

```bash
python3 -m scripts.security_scan --rescan-all
```

### 2.4 风险结论

任一 block 命中 → `risk: high`；仅 warn → `medium`；无 → `clean`。
**high 不阻止入库**，由人工后续处理（打标签 + 报告，供审核）。

## 三、审核标准

| 维度 | 标准 |
| ------ | ------ |
| 价值 | 有明确使用场景，能解决实际问题 |
| 安全 | 无高风险（high 需人工判定是否误报） |
| 内容 | 入库后应补中文描述 + 推荐理由 + 标签 |
| 版本 | 首次入库 v1.0.0；同步上游更新时 patch+1 |
| 维护 | 上游仓库活跃（有更新迹象） |

## 四、提交规范

```bash
# 建议的 commit 消息格式
feat: 入库 <owner>/<repo>（N 个 skill）
docs: 补充 xxx 文档
fix: 修复 xxx
ci: 调整 xxx 工作流
```

## 五、GitHub Actions

| 工作流 | 触发 | 作用 |
|--------|------|------|
| `check-updates.yml` | 每日 03:00 UTC | 自动同步上游更新（无 key 依赖） |
| `deploy-site.yml` | push main + 手动 | 自动生成并部署 GitHub Pages 站点 |

> 站点产物在 `web/`，由 `scripts/web.py` 生成，**不要手动编辑**。
