# 架构说明

> 本仓库（agent-skills-registry）是 AI Skills 精选源，纯镜像模式。本文说明其结构、数据模型与设计决策（1-3）。设计源参考见 [README.md](README.md)。

## 一、仓库定位

从 GitHub 搜集 AI Agent Skills 入库，统一维护版本与安全标签，供 `agent-skills-manager` (asm CLI) 作为唯一安装源。采用**纯镜像模式**——直接存放 skill 源码 + 总索引，安装不依赖上游仓库可用性。

## 二、目录结构

```
├── index.yaml       ← 仓库级装订页（每 skill 一行：id/name/version/risk/category）
├── rules.yaml       ← 安全扫描规则库（R1-R5，增删规则不改代码）
├── skills/          ← 实际的 skill 文件（镜像，按 来源仓库/分类/skill 分层）
│   └── <owner>/<repo>/[<category>/]<skill>/
│       ├── SKILL.md          skill 主文件（含 YAML frontmatter：name/description）
│       ├── ...               上游辅助文件（原样保留，含分类 README）
│       ├── skill-meta.yaml   skill 级元数据
│       └── security-report.md 安全扫描报告（入库时生成）
├── scripts/         ← 维护脚本（见维护手册.md）
├── web/             ← 站点产物（web.py 生成，GitHub Pages 部署）
└── docs/            ← 本文档
```

## 三、数据流（五环管道）

```
GitHub 上游（多来源仓库）
   │  import.py（首次入库）
   ▼
skills/<owner>/<repo>/[<category>/]<skill>/    ← 纯镜像
   │  security_scan.py（入库自动扫描）
   ▼
skill-meta.yaml（risk 标签）+ security-report.md
   │  translate.py（手动，低谷时段）
   ▼
description_zh（中文描述）
   │  enrich.py（手动，低谷时段）
   ▼
recommendation + tags（内容化）
   │  index.yaml（装订页汇总）
   ▼
sync.py（GitHub Action 每日自动同步上游）
   │
   ▼
web.py（GitHub Action 自动部署站点）
```

## 四、决策 1 · skills/ 目录按来源仓库分层

**结构**：`skills/<owner>/<repo>/[<category>/]<skill>/`

- 顶层 = 来源仓库（owner/repo），避免跨仓库重名（`code-review`/`handoff` 等通用名几乎每个合集都有）
- 后续层级 = 上游原样保留（含分类目录及其中 README.md）
- 唯一标识（id）= `owner/repo/[category/]skill-name`
- 单 skill 仓库落在 `skills/<owner>/<repo>/<skill>/`（无 category 层）

**代价**（镜像 + 溯源模式下可接受）：路径变长；同一逻辑 skill 从多来源来会存多份，由索引层标注而非目录去重。

## 五、决策 2 · 分布式元数据 + 轻量索引

两级 YAML 分工：

| 文件 | 层级 | 角色 | 维护侧 |
|------|------|------|--------|
| `skill-meta.yaml` | skill 级 | 单 skill 详情（version/upstream_sha/risk/description_zh/recommendation/tags/source） | import/sync 写，CLI 按需读 |
| `index.yaml` | 仓库级 | 装订页（schema version + updated_at + 每 skill 一行精简快照） | 由各 skill 的 meta 汇总生成，供全局扫描 |

**skill-meta.yaml 示例**：

```yaml
name: code-review
source:
  owner: mattpocock
  repo: skills
  category: engineering
  path_in_repo: skills/engineering/code-review
upstream_branch: main
upstream_sha: abc1234
version: 1.0.0
last_synced_at: '2026-08-25'
risk: clean
description_zh: 按两轴审查代码改动…
recommendation: 适合需要审查代码质量的开发者…
tags: [编码, 代码审查, 工作流]
```

> `description_en` 不重复维护——从 `SKILL.md` frontmatter 读取（源已自带）。

**index.yaml 示例**（装订页，每 skill 一行）：

```yaml
version: 1
updated_at: '2026-08-25T12:00:00+00:00'
skills:
  - id: mattpocock/skills/engineering/code-review
    name: code-review
    version: 1.0.0
    risk: clean
    category: engineering
```

**分界**：`skill-meta.yaml` 管「单点精确读」（写侧主力）；`index.yaml` 管「全局聚合扫描」（CLI 的 check/update/list 用 O(1) 次请求扫全部版本）。index 永不做详情，单 skill 更新只改写一行，天然错开并发冲突。

## 六、决策 3 · 全链路统一 YAML

1. 本项目 YAML 已无处不在——`SKILL.md` frontmatter、`skill-meta.yaml`、`index.yaml`、CLI 本地 `skills.yaml`；JSON 反而是异类。
2. 全链路只用 `PyYAML`（`yaml.safe_load` 亦能解析 JSON），一个解析器、一套心智。
3. YAML 可注释、可读性好，适配「人工审核的精选索引」性质。
4. 零新增依赖。

## 七、安全扫描模型

安全扫描是核心差异化（源头把关一次、所有用户受益）。规则库 `rules.yaml` 独立于引擎 `security_scan.py`（增删规则不改代码）。

| 规则 | severity | 内容 | 形态 |
| ------ | ---------- | ------ | ------ |
| R1 危险命令 | block | `rm -rf /`、`curl\|bash`、`sudo`+高危、`eval`+危险组合等 | 正则 + pair 同行组合 |
| R2 敏感凭据 | block | 密钥前缀（sk-/ghp_/AKIA/私钥块）、带引号赋值、高熵值 | 正则 |
| R3 数据外传 | warn | 读本地文件 + 发远程组合 | pair 同文件 |
| R4 操纵性指令 | block | prompt 注入：忽略先前指令/索取 system prompt | 正则 |
| R5 依赖来源 | warn | curl 安装脚本指向非知名来源 | 正则 |

**风险结论**：任一 block 命中 → `high`；仅 warn → `medium`；无 → `clean`。high **不阻止入库**（由人工后续处理），只打标签 + 出报告。

**关键规则设计经验**：

- pair 组合检测有 `scope: same_line`（同行组合）和 `same_file`（同文件），避免无关代码被组合误报
- R2 的 `token=` 需区分"变量赋值"与"真实凭据"（带引号/高熵才命中），否则 `TOKEN = generateToken()` 这类合法代码被误报
- 扫描跳过自身产物（skill-meta.yaml、security-report.md），防自我污染

详见 [贡献指南.md](贡献指南.md#安全规则) 的规则增删方法。
